# 问渊项目沟通管理计划

## 1. 小组分工

小组共 5 人，建议按以下职责分工，姓名可按实际情况填写。日常使用组内聊天群沟通，代码和文档统一保存在 GitHub 仓库。

| 成员分工 | 主要职责 |
|---|---|
| 组长 | 任务分配、进度跟踪、需求整理和文档汇总 |
| 出题开发 | AI 题目生成、题库和提示词调整 |
| 汤主与队友开发 | 汤主判题、AI 队友推理和提示功能 |
| 前端开发 | 页面设计、交互实现和接口联调 |
| 测试与部署 | 功能测试、问题记录、运行部署和演示准备 |

## 2. 沟通安排

| 沟通内容 | 沟通频度 | 沟通方式 | 产出物 | 责任人 |
|---|---|---|---|---|
| 分析：确定游戏功能、项目范围和成员分工 | 项目开始时一次，需求调整时及时沟通 | 组内讨论、面对面交流 | 需求说明、分工表 | 组长 |
| 设计：确定页面流程、模块接口和汤底信息的可见范围 | 设计阶段每周一次 | 线上会议、GitHub 文档 | 页面原型、接口说明 | 前端开发牵头，开发成员参与 |
| 开发：同步各模块进度、遇到的问题和下一步任务 | 每周一次，遇到阻碍及时沟通 | 组内聊天群、简短例会 | 任务清单、待解决问题 | 组长 |
| 开发：讨论题目质量、汤主判题和 AI 队友表现 | 每周一次，发现错误及时反馈 | 组内聊天群、运行演示 | 提示词修改、问题样例、代码 | 出题开发、汤主与队友开发 |
| 开发：核对接口，联调选题、提问、交卷和复盘流程 | 模块完成时及接口修改后 | GitHub PR、线上联调 | 联调代码、接口修改记录 | 前端开发 |
| 测试：反馈功能缺陷，确认修复结果 | 测试阶段每天简短同步 | 组内聊天群、GitHub Issue | 问题清单、测试结果 | 测试与部署 |
| 发布：检查启动步骤、功能完整性和答辩演示材料 | 每次发布或答辩前一次 | 全组试运行、面对面交流 | 可运行版本、使用说明、演示材料 | 测试与部署 |
| 运行维护：处理使用反馈，修复问题并总结经验 | 每周汇总，严重问题即时沟通 | 组内聊天群、GitHub Issue | 修复代码、更新说明、项目总结 | 组长协调，相关成员处理 |

## 3. 简单约定

- 每周例会控制在 20–30 分钟，只讨论进度、问题和下周任务。
- 重要结论简单记下“做什么、谁负责、何时完成”，保存在仓库中。
- 遇到影响其他成员或项目交付的问题及时在群里说明，由组长协调处理。
