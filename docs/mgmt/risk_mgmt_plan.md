# 问渊项目风险管理计划

## 1. 管理方式

本计划适用于 5 人小组，成员分工见[沟通管理计划](communication_mgmt_plan.md)。每周例会顺便检查风险；出现问题时，由相关成员处理，组长协调。

影响程度、工作量影响、进度和成本影响均按高、中、低估计。优先权表示紧急程度：高为优先处理，中为本周安排处理，低为持续观察。以下为可能出现的风险，不表示问题已经发生。

## 2. 风险清单

| 风险名称 | 所属维度 | 风险说明 | 影响程度（重要性） | 对工作量的影响 | 对进度和成本的影响 | 优先权（紧急程度） | 跟踪频率 |
|---|---|---|---|---|---|---|---|
| R1 需求变化 | 项目管理 | 功能范围不清或不断增加新功能，造成反复修改 | 高 | 高 | 高 | 高 | 每周，需求变更时及时检查 |
| R2 成员时间冲突 | 资源、进度 | 课程、考试等占用时间，导致任务延期 | 高 | 中 | 高 | 高 | 每周 |
| R3 AI 输出不稳定 | 技术 | 题目逻辑不完整、汤主回答矛盾或队友提示不合理，影响游戏体验 | 高 | 高 | 中 | 高 | 每次提示词修改后 |
| R4 答案或密钥泄露 | 技术、安全 | 接口提前返回汤底，或将 API Key 提交到仓库 | 高 | 中 | 高 | 高 | 每次提交及发布前 |
| R5 模型接口异常 | 外部因素、成本 | 网络故障、调用限流或额度不足，使生成和问答无法正常进行 | 高 | 中 | 中 | 高 | 每周，演示前检查 |
| R6 模块对接困难 | 技术 | 前端与 AI 模块的接口字段或流程不一致，导致联调失败 | 中 | 中 | 中 | 中 | 每次联调时 |
| R7 测试不充分 | 项目管理、质量 | 测试时间不足，遗漏超时、刷新、重复点击等异常情况 | 高 | 中 | 高 | 高 | 测试阶段每天 |
| R8 演示环境异常 | 外部因素 | 演示设备缺少配置、端口冲突或网络不稳定，导致项目无法运行 | 高 | 低 | 中 | 高 | 发布及答辩前 |

## 3. 简要应对措施

| 对应风险 | 责任人 | 应对措施 |
|---|---|---|
| R1 需求变化 | 组长 | 先确定必须完成的功能；新增需求全组讨论，优先保证游戏完整流程。 |
| R2 成员时间冲突 | 组长 | 提前了解成员时间，把任务拆小；有延期及时说明，必要时互相接手。 |
| R3 AI 输出不稳定 | 出题开发、汤主与队友开发 | 准备固定题目和问答样例，调整提示词后重新测试；保留已验证的题目用于演示。 |
| R4 答案或密钥泄露 | 汤主与队友开发、测试与部署 | 检查汤底的可见范围；密钥放在本地环境配置中，不提交仓库；发现密钥泄露立即更换。 |
| R5 模型接口异常 | 出题开发 | 提前检查连接和剩余额度，减少重复调用；演示时准备离线模式，并说明其功能限制。 |
| R6 模块对接困难 | 前端开发 | 开发前约定接口字段和错误提示；尽早联调，修改接口时及时通知相关成员。 |
| R7 测试不充分 | 测试与部署 | 预留测试时间，覆盖正常流程和常见异常；修复问题后再测一次。 |
| R8 演示环境异常 | 测试与部署 | 在实际演示设备上提前完整运行一次，备份可用版本和演示录像。 |

发现新风险或风险程度变化时，在本表中补充或调整；问题解决后，简单记录处理结果。
